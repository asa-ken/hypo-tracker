# DESIGN_PRINCIPLES.md

## 目的
hypo-trackerのUI判断を、画面ごとの好みではなく、認知負荷・情報構造・操作性・実運用の観点から一貫して行うための判断基準。

## 1. Information First
- 情報量は必要なものを削らない。
- 減らす対象は、情報そのものではなく、情報が持つ視覚的な主張。
- 線、枠、色、バッジ、矢印、アイコン、ラベルは、意味を追加しない限り増やさない。
- 情報階層は余白、位置、文字サイズ、太さ、グルーピングを優先して表現する。

## 2. Cognitive Load
- 画面を見た瞬間に「何が重要か」「何が操作できるか」「今どの状態か」が分かる構造を優先する。
- 同じ意味のUIは同じ視覚言語を使う。
- ユーザーが同じ情報を複数箇所へ移す必要がある場合は、コピペ疲れとして問題候補にする。
- ラベルは意味を説明するだけでなく、義務感・不足感・専門用語による負荷も評価する。

## 3. State without Pressure
- 状態は明確に示す。
- 状態表示から、ユーザーが「やらなければならない」と感じる圧力を必要以上に作らない。
- 「要更新」「不足」など、状態と行動指示を一体化させない。
- 「データなし」は状態の説明であり、「未取得」は行動を要求する表現になり得るため、文脈で使い分ける。

## 4. Visual Weight
各要素を存在の有無だけで評価しない。太さ、コントラスト、面積、色、枠、余白、アイコンサイズ、配置を含めて画面上の主張の強さを評価する。
同じ強さの要素が増えすぎている場合、情報を削る前に視覚的重量を下げる。

## 5. 操作性
- タップ領域は `docs/design/DESIGN_SYSTEM.md` の仕様に従う。
- 見た目を軽くするために操作領域を小さくしない。
- シート、行、編集領域、開閉、スワイプ等の操作は、見た目と実際のヒット領域を分けて評価する。
- iPhone想定の実画面で確認する。

## 6. 実画面を基準にする
コード上の整合性だけで完了としない。実データを入れたレンダリング結果、DOM、画素、スクロール、実操作を確認する。測定手順は `DESIGN_SCORECARD.md` と `UI_REVIEW_LOOP.md` に従う。

## 7. 判断の優先順位
1. 破綻・操作不能・重大なアクセシビリティ問題
2. 認知負荷・操作摩擦
3. 情報構造
4. 視覚的ノイズ
5. 一貫性
6. 情報密度と画面効率
7. 細かな視覚的洗練
8. 装飾

既存トークンの定義は `DESIGN_SYSTEM.md` を一次定義とする。Evidence Hierarchy は `DESIGN_SCORECARD.md` を一次定義とし、ここで再定義しない。

**この優先順位は欠陥の深刻度を並べたものであり、`UI_REVIEW_LOOP.md` Phase 1.5b で見つかる
「機会」(何も壊れていないが価値を足せる候補)はこの並びに直接は乗らない。** 採用と判定された機会候補は、
1〜2(破綻・認知負荷)がある間はそちらを優先する。1〜2が無い周だけ、その周のテーマにしてよい。

## 8. 実画面に即した判断例
### ホーム
カードを増やす前に、同じ情報が別カード・リマインダー・詳細へ重複していないか確認する。区切り線やバッジを足す前に、余白と見出し構造だけでグループが伝わるかを見る。

### 市場・銘柄分析
市場カードと銘柄カードの重要度を色や枠だけで競わせない。分析の種類が違うことは構造で示し、同じ意味の開閉・状態・操作は同じ視覚言語にする。

### 銘柄詳細
情報量が多いこと自体を問題にしない。主要指標、業績推移、注目ポイント、メモ等の関係を余白・見出し・開閉で整理し、同じ内容を複数の場所に見せる冗長性を探す。

### 取り込み（会話を取り込む）
外部AIの出力を貼り付けるという中心ワークフローを優先する。コピー、画面切替、貼り付け、確認を何度も要求する設計を摩擦として扱う。差分表示は「何が変わったか」を理解するために使い、装飾として増やさない。

### リマインダー一覧・詳細
リマインダーと元情報の関係を理解するために必要な情報は残す。ただし、リマインダーを開けば読める内容を一覧にも全文表示するなど、二重表示は検討対象にする。

### 設定
設定項目を目立たせることより、現在値・変更可能性・変更結果を明確にする。通常利用の画面と同じ視覚言語を使い、設定専用の装飾を増やさない。

### 各シート（注目ポイント編集 / 指標編集 / 業績推移編集）
編集操作を明確にしつつ、保存・キャンセル等の操作UIがコンテンツより強くならないようにする。入力欄はiOS自動ズーム回避の16pxを維持する。

## 9. ラベルの原則
ラベルは機能説明だけで決めない。心理的負荷、専門性、行動要求、重複性を評価する。「仮説」→「注目ポイント」は対応済みの意思決定であり、その決定理由(専門用語の心理的負荷)が今も成り立つ前提でのみ再提案しない。詳細は `DECISIONS.md` を参照する。
