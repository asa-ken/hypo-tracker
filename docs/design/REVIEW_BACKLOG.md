# REVIEW_BACKLOG.md

## 使い方
自律レビューの巡回対象。1周につき1画面・1テーマを扱う。レビュー終了時に最終レビュー日、直近の指摘、状態を更新する。

状態は `要レビュー` / `保留` / `完了` のいずれか。

## 機会バックログの使い方
`UI_REVIEW_LOOP.md` Phase 1.5b で見つけた「機会」候補を記録する。欠陥バックログ(上記の対象画面表)とは
別に管理する。理由は、欠陥は直せば消えるが、機会は**見送っても価値が消えるわけではなく**、
前提が変わったときに再評価すべきものだから。

- 「画面ごとの機会」は、その画面のPhase 1.5b実施時に見つけたもの。表の直近の指摘欄からもリンクする。
- 「画面横断の機会」は、通し実行の途中で他画面にも関わると分かったもの。
- 各候補は「候補 / 効果 / コスト / 代替 / 判定(採用・見送りと理由)」をセットで書く。
- 見送った候補も削除しない。前提が変わったら見直す(`DESIGN_SCORECARD.md`「対応済みの意思決定」参照)。

### 残っているもの(トークン定義の判断が要る)

**Accessibility=2 / 補助情報のコントラスト不足**
`--ink3`(#8b95a1)はどの地色でもAAに届かない(白3.04 / app2.86)。
`.hint` と `.btn.ghost` は `--ink2` にしたが、次が残っている。

- `.list-row .meta`(11px・白地3.04:1) … 銘柄コード、件数、次回日時など。全画面に多数
- `.muted`(12px・app地2.86:1) … 空区分の「なし」
- `.empty` の案内文(16px・app地2.86:1) … ゼロ状態の説明。ホーム含む4画面で共通

**なぜ自律で直さないか:** `--ink3` を色味を保ったままAAに届かせると `--ink2`(#5a6672)より濃くなり、
文字色の3段階(ink / ink2 / ink3)が実質2段階に潰れる。これはトークン定義の変更にあたる。
選択肢は「濃くして階層を諦める」「該当箇所を個別に `--ink2` へ寄せる」「文字サイズを上げて大文字扱い(3:1)にする」「現状を許容すると明示的に決める」。

### 🔴 新たに発見(2026-08-15): 業績推移の部分更新で、貼り付けに無い年度のデータが削除される
「変更年度だけ強調表示する」機会候補(上記)の実装に着手した際、その前提となる差分表示の仕組みを調べたところ、
より重大な問題を発見した。**業績推移の更新は年度ごとの塊を丸ごと入れ替える仕様**(`commitImport()`)のため、
GPTの回答に一部の年度しか含まれていないと、貼り付け文に無い年度のデータが取り込み時に削除される。

実データで検証: 日東工器(6151)の売上高は本来5年分(23〜27年3月期)のデータを持つが、
「27年3月期(予)=33800」の1行だけを貼って取り込んだところ、他の4年分が消えた
(`stock('6151').trend['売上高']`が`{unit, "27年3月期(予)":"33800"}`だけになった)。

四半期ごとに「今回の予想値だけ」を聞く使い方は自然に起こりうるため、実運用で踏む可能性がある。
表示(差分プレビュー)は一応この挙動を「更新前」列で示してはいるが、文字レベルの差分表示に埋もれており、
何年分のデータが消えるのかが一目では伝わらない。

**対応方針の判断が必要(保存挙動の変更にあたるためユーザー確認が要る)。** 考えられる案:
- A. 業績推移の取り込みを「丸ごと入れ替え」から「年度ごとにマージ(貼り付けにある年度だけ更新、無い年度は保持)」に変更する
- B. 丸ごと入れ替えの仕様は維持しつつ、消える年度を明示的に警告する(例:「23年3月期・24年3月期・25年3月期・26年3月期のデータが削除されます」)
- C. 両方(通常はマージ、意図的に年度を減らしたい場合だけ明示的な操作を要求する)
