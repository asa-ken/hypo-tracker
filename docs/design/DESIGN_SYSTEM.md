# DESIGN_SYSTEM.md

## この文書の位置付け
ここがhypo-trackerの**デザイントークンとコンポーネントの一次定義**。実装時は `index.html` の `:root` と `test/e2e/design.js` の契約を一致させる。

各項目に「検査」を明記する。**検査がある項目とない項目を混同しないこと。** 検査がない項目は、テストが通っていることをもって遵守の証拠にできない。

現時点で機械検査されているのは次の8つ。

| 対象 | 検査 |
|---|---|
| spacing(`gap` のみ) | `design.js` 観点F |
| typography | `design.js` 観点A |
| color | `colortoken.js` |
| タップ領域 | `design.js` 観点D / `sheettap.js` |
| escaping | `escuse.js` |
| コンポーネント(カード状コンテナの登録) | `component.js` |
| 線の量(border の本数) | `visualnoise.js` |
| 面積と高さ(`ink` / `colored` / `scrollHeight`) | `shotmetrics.js` |

padding / margin は契約の対象外。

## Spacing
使用する余白は次の4段階だけ。
- `--sp1: 4px`
- `--sp2: 8px`
- `--sp3: 12px`
- `--sp4: 16px`

6px、3px等の新しい値を導入しない。

**検査あり(gapのみ)**: `test/e2e/design.js` の観点F が `index.html` の `gap:Npx` を集計し、`4/8/12/16` 以外を検出する。

**検査なし(padding / margin)**: padding と margin はトークン化されていない。実際に `padding:10px 12px`(入力欄)などトークン外の値が存在し、それが正しい実装として `design.js` の観点A で検査されている。**padding / margin をトークン逸脱として一括修正しないこと。** 拡張したい場合は独立したテーマとして `REVIEW_BACKLOG.md` に起票する。

## Typography
本文・UIの文字サイズは次の5段階。
- 11px … 日付・単位・補足(最小)
- 12px … 補助テキスト
- 13px … 本文
- 15px … 強調・小見出し
- 17px … 画面タイトル・指標の数値

入力欄のみ16pxを使用し、iOSの自動ズームを回避する。したがって合計6種類以内。

**11px は許容する。禁止は 11px 未満。** 通勤中にスマホで読む前提のため10px以下は使わない。

**検査あり**: `test/e2e/design.js` の観点A が font-size の種類数(6以内)、最小値(11以上)、入力欄16pxを検査する。

**検査あり**: `test/e2e/colortoken.js` が次を見る。

- `:root` の色トークンが17個そろい、名前がこの文書と一致すること
- `:root` の外に新しい色リテラルが増えていないこと(既知の例外は同ファイルにリスト化)
- 色の直書き箇所が13件から増えていないこと

既知の例外は現在10種類(不透明5・半透明5)。影とスクリムの半透明は平坦なトークンで表せないため別枠で許している。例外を増やすときは `DECISIONS.md` に理由を書き、`colortoken.js` のリストへ追記する。

局所的な残色(角丸クリップの縁など)は `test/e2e/png.js` の画素スキャンで測定できる。これは逸脱検査ではなく、個別の描画不良を測る手段。

## Interaction
- タップ可能領域は44pxを下限とする。
- 指標グリッドは2列。

**検査あり(主要画面)**: `design.js` の観点D が `home` / `analysis` / `import` / `reminder` の4画面について、`#view button`、`.list-row`、`.sub-row`、`.sec .h` の高さを検査する。

**検査あり(シート)**: `test/e2e/sheettap.js` が注目ポイント編集 / 指標の管理 / 指標編集(主要指標・業績推移) / リマインダー追加の各シートを開き、`button`・`select`・`[onclick]`・`.list-row`・`.sub-row`・`.chip`・`a` の高さを検査する。

**検査の範囲外**: 上記に含まれないシートとセレクタ。新しいシートを足したら `sheettap.js` に追加する。

指標グリッドの2列は観点A で検査する。

## Escaping
- HTMLへ挿入する値は `esc()` を使う。
- `onclick` 内のJS文字列引数には `escArg()` を使う。
- 2つを用途混同しない。

**検査あり**: `test/e2e/escuse.js` が次を見る。

- `esc()` / `escArg()` の定義が残っていること
- `onclick` 等のイベント属性の中で `esc()` を使っていないこと(アポストロフィで属性が割れる)
- `escArg()` が必ず `'${escArg(x)}'` の形、つまりJSの文字列引数として使われていること

判定をシングルクォートの有無で行うのは、`statBadge(on, \`toggleMetric('snap','${escArg(k)}')\`)` のようにハンドラ文字列をヘルパーへ渡す間接的な形があるため。属性の字面だけで探すと、この形を誤検知する。

## Components

トークン(色・文字サイズ・余白)の一段上にある「部品」の一次定義。**ここに載っているものから選ぶ。載っていない形が必要になったら、まずここに足せないかを検討する。**

この節は2026-08-22に新設した。それまでトークンは17色・6段階まで定義して機械検査していたのに、
そのトークンを使う部品の側は無定義で、同じ役割のカードが2実装(`.failbox` と `.candbox`)並存しても
検査が全部通ってしまった(色もサイズもタップ領域も正しかったため)。実際にユーザー指摘で発覚し、
2026-08-22のPR #155で統合した。経緯は `REVIEW_BACKLOG.md`「プロセスの欠陥」を参照。

### コンテナ(内側に他の要素を入れる箱)

| クラス | 用途 | 構造 | 注意 |
|---|---|---|---|
| `.card` | 汎用の白カード。単独の情報の塊 | 枠線あり・角丸12px・`padding:13px 14px` | `.card.tap` でタップ可能にする。**一覧を作るときは使わない**(下記`.list`) |
| `.list` | 一覧。カードを積むのではなく1枚の枠に行を並べる | `.list > .list-row` または `.list > .swipe > .list-row` | カード1件ごとに影と余白が付くと、件数が増えたとき全部が同じ強さで主張してしまうため |
| `.list.flat` | 区分の中身として並ぶ一覧 | 白カード・枠線・区切り線なし。字下げだけで従属を示す | 中身が空のカードは文字を薄く細く(`:not(.filled)`) |
| `.list.cards` | 1枚ずつ独立した白カードとして並べる | 線を引かず地色の隙間で切れ目を作る | 角丸は`.swipe`の切り抜きで作る |
| `.candbox` | 取り込み画面の確認カード | `.cbx-head`(見出し+説明、地色`--bg`) + `.cbx-body`(内訳、白) | **外枠と行の区切り線は引かない。**領域の違いは背景色だけで示す(2026-08-22) |
| `.sec` | 開閉できるセクション | `.sec > .h`(見出し) + `.sec > .b`(中身)、`.sec.open`で開く | 子孫セレクタでなく**直下(`>`)**で書く。入れ子の`.sec`が誤動作するため |
| `.sheet` | 下から出るシート | `.sheet .headbar`(上端固定の操作列) + 本文 | 操作はシート上端の`headbar`に集める。全幅ボタンを積まない |
| `.banner` | 消えない注意書き。押した場所のすぐそばに置く | 1段落。`.banner.warn`でamber | トーストは数秒で消えるため、残す必要がある注意はこちら |

### 行・セル

| クラス | 用途 | 構造 | 注意 |
|---|---|---|---|
| `.list-row` | 一覧の1行 | `.lt`(左・主情報) + `.rt`(右・補助) 、`.ttl`/`.meta`/`.arrow` | `min-height:44px`。区切り線は`border-top`、先頭行だけ無し |
| `.swipe` | 行を右→左スワイプで削除できるようにする帯 | `.swipe > .list-row` + `.swipe > .del-btn` | `.list-row`自体は変えず、区切り線だけこの帯に付け替える |
| `.metric` | 指標の2列グリッド | `.metric > .m`、`.m .k`/`.v`/`.d`、`.m.stale`で古い値 | **2列固定。**3列だと1セル約95pxで指標名が必ず折り返す |
| `table.trend` | 業績推移テーブル | 1行目`th`は縦固定、1列目は横固定(`position:sticky`) | 指標名列は`width:125px`固定+`.clip2`で2行クランプ |

### 見出し・ラベル

| クラス | 用途 | 構造 | 注意 |
|---|---|---|---|
| `.lbl` | 画面の区切り見出し | 12px・`--ink2`・太字 | |
| `.lbl.grp` | 開閉できる区分見出し | `.grp-right` > `.grp-edit` + `.grp-caret` | 見出し全体がタップ領域(52px)。編集リンクは44px枠で包み16px離す |
| `.lbl.head` | 開閉しない区分見出し | `.lbl.grp`と大きさ・色・区切り線を揃える | 矢尻が無いことだけが違い |

線は**区分の変わり目だけ**に引く。行ごとの線やアクセントバーは引かない。

### 入力・操作

| クラス | 用途 | 構造 | 注意 |
|---|---|---|---|
| `.fld` | 入力欄1件(ラベル+入力) | `label.fld > .t`(ラベル) + `input`等 | 入力欄は16px(iOSの自動ズーム回避) |
| `.seg` | セグメント切替(全幅) | `.seg > button`、選択中は`.on` | |
| `.seg.light` | 補助的な切替(文字幅のピル) | 地色の上に置き、選択中だけ白く浮かせる | 全幅の紺ベタは面積が大きく重いため |

### 状態・ユーティリティ

| クラス | 用途 | 注意 |
|---|---|---|
| `.empty` | ゼロ状態の案内(画面・一覧が丸ごと空) | `.empty > .big`が主文。空白のまま放置しない |
| `.nodata` | 個別の枠の中にデータが無いことの表示 | 破線の枠+地色。**画面全体が空のときは`.empty`を使う**(こちらはグラフ枠など、周りに他の情報がある中の一部が空の場合)。表のセルの中では`.nodata-cell` |
| `.toast` | 数秒で消える完了通知 | 画面下部中央に固定。`toast()`関数から使い、直接マークアップしない。**消えて困る注意書きには使わない**(その場合は`.banner`) |
| `.clip3` | 3行クランプ(タップで全文) | `display:-webkit-box`。**flexアイテムにしない**(行数が不安定になる)。実際に溢れている場合だけJS(`markClip3Truncated`)が`.tapmark`を付ける |
| `.metwarn` | `.candbox`の警告バリアント | `class="candbox metwarn"`で使う。**色の上書きだけを担当**し、構造は`.candbox`と完全に共有する。背景色は他のカードと同じ`--bg`で、警告の合図はアイコンと文字色のみ(2026-08-22) |

| クラス | 状態 |
|---|---|
| `.failbox` | **新規使用しない。**「調べる項目を選ぶ」画面の「項目が多すぎます」1箇所だけで残存。取り込み画面の「読めなかった行」は2026-08-22に`.candbox.metwarn`へ統合済み。将来的に`.candbox`へ吸収する候補だが、別画面の見た目が変わるためユーザー確認が要る |

### 検査

**検査あり**: `test/e2e/component.js` が「カード状のコンテナ」(単独クラスのセレクタで`border-radius`と`background:var(--*)`を両方持つもの)を`index.html`から抽出し、登録済みの一覧と一致するかを見る。

新しいカード状のコンテナを足すと**失敗する**。これは「独自UIが増えたらコンポーネントへ戻す」を強制するための検査で、意図的に増やす場合は `component.js` の一覧へ追記し、既存コンポーネントで代替できない理由を `DECISIONS.md` に書く。

**検査の範囲外**: 上の表に書いた構造(子要素の組み合わせ・用途の使い分け)は機械検査していない。表と実装がずれていないかは、この節を読んで判断する。

## 変更境界
トークンの定義そのものを変更するにはユーザー確認が必要。対象はspacing、font-size、color、44pxの下限、2列グリッド、escaping契約を含む。

個別コンポーネントの配置・構造変更は、既存トークンを守る限り自律判断できる。

## 逸脱を見つけた場合
まず既存トークンに合わせて実装できない理由を確認する。トークンを変更して解決する前に、使用箇所・波及範囲・代替案・E2E影響を整理し、ユーザーへ提示する。
