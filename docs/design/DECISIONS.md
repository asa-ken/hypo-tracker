# DECISIONS.md

追記型の意思決定ログ。既存判断を再検討するときも過去エントリを削除・上書きせず、新しいエントリを追加する。

## エントリ形式
- **Date:** YYYY-MM-DD
- **Problem:** 問題
- **Decision:** 採用した判断
- **Reason:** 判断理由
- **Evidence:** 実測、ユーザー行動、テスト、画素測定等
- **Status:** 採用 | 撤回

## 初期エントリ

### 2026-08-09 — 角丸クリップの残色
- **Problem:** 角丸クリップの縁に下の要素の色が残った。目視とCSS契約テストでは消えたと誤判定した。
- **Decision:** 切り抜き12pxに対して子要素の角丸を16pxにする。
- **Reason:** 曲線を内側へ逃がすことで残色を消す。
- **Evidence:** PNG画素測定で赤み最大16/128画素の残存を確認。isolation / contain:paint / will-change / translateZ は無効。角丸14pxでは赤み2、16pxで0。
- **Status:** 採用

### 2026-08-09 — 「他2件と同じ」バッジ
- **Problem:** バッジの文言だけでは意図を説明しきれず、視覚的な主張も増えた。
- **Decision:** 「他2件と同じ」バッジを撤回。
- **Reason:** 情報価値より説明不足と視覚ノイズが大きい。
- **Evidence:** 実運用で意図を十分に伝えられないと判断。
- **Status:** 撤回

### 2026-08-09 — 折りたたみボタン

- **Reason:** 同一操作を二つのUIで表すため、操作構造が冗長になる。
- **Evidence:** 実画面で見出しの開閉と機能が重複。
- **Status:** 撤回

### 2026-08-09 — triageシート
- **Problem:** リマインダー登録までの導線が深くなった。
- **Decision:** triageシートを撤回。関連コード(`sheetReminderTriage` / `triageRemove` / `triageAddReminder` / `STATE._triageItems`)を削除。
- **Reason:** 目的達成までの操作摩擦が増えた。リマインダー登録は取り込み画面へ前倒しした。
- **Evidence:** 実運用で導線の深さを確認。
- **Status:** 撤回

### 2026-08-09 — 注目カードの本文一覧
- **Problem:** リマインダーを開けば同じ内容が読めるため本文一覧が冗長だった。
- **Decision:** 注目カードの本文一覧を撤回。代わりにリマインダー詳細の対象一覧をタップ可能にして編集経路を保全。
- **Reason:** 同一情報の重複表示を避ける。ツリー状に見せる意味がない。
- **Evidence:** リマインダー詳細との情報重複を確認。
- **Status:** 撤回

### 2026-08-09 — 「仮説」→「注目ポイント」

- **Decision:** UI上の名称を「注目ポイント」に変更。
- **Reason:** 同じ機能的意味を保ちつつ、断定・検証を要求する印象を下げる。
- **Evidence:** 過去のUI改善で変更完了。
- **Status:** 採用

### 2026-08-09 — spacing tokenからの逸脱をテストが検出
- **Problem:** 実装中に `gap:6px` と `gap:3px` を導入し、`test/e2e/design.js` の観点Fが落ちた。
- **Decision:** 8px / 4px に修正し、4段階を維持。
- **Reason:** カードごとに詰まり方が変わるのを防ぐ。
- **Evidence:** 人間のレビューではなくテストが捕まえた。トークン契約を機械検査する価値の実例。
- **Status:** 採用

### 2026-08-09 — 無検査だったデザイン契約を機械検査下に置く
- **Problem:** `design.js` は font-size / gap / 主要4画面の44px しか見ておらず、色トークン・`esc()`/`escArg()` の使い分け・シート内のタップ領域が無検査だった。文書側には「design.js が検査する」と書かれており、実装と食い違っていた。
- **Decision:** `colortoken.js` / `escuse.js` / `sheettap.js` の3スイートを追加。`DESIGN_SYSTEM.md` の各項目に「検査あり/なし/範囲」を明記した。
- **Reason:** テストが通ることを遵守の証拠にできない項目があると、自律ループが誤った安心を得る。
- **Evidence:** 負のテストで、色の追加・トークン削除・onclick内の `esc()` 誤用・HTML本文への `escArg()` 混入が、いずれも検出されることを確認した。
- **Status:** 採用

### 2026-08-09 — シート内のタップ領域44px
- **Problem:** シートを実測したところ、指標の管理の「表示中/非表示中」バッジが36px(12個)、指標編集とリマインダー追加の `select` が43pxで、44pxの下限を割っていた。主要4画面しか見ていない `design.js` では検出できなかった。
- **Decision:** `.stat` の `min-height` を36px→44px、`select` に `min-height:44px` を追加。`metstat.js` の閾値も36→44へ引き上げた。
- **Reason:** アクセシビリティは Decision Hierarchy の最上位。selectは43pxで、あと1pxという「気づかれない不足」だった。
- **Evidence:** 修正前に `sheettap.js` が6項目落ちることを確認してから修正した。
- **Status:** 採用
