# DECISIONS.md

追記型の意思決定ログ。既存判断を再検討するときも過去エントリを削除・上書きせず、新しいエントリを追加する。

## エントリ形式
- **Date:** YYYY-MM-DD
- **Problem:** 問題
- **Decision:** 採用した判断
- **Reason:** 判断理由
- **Evidence:** 実測、ユーザー行動、テスト、画素測定等
- **Status:** 採用 | 撤回

### 2026-08-09 — ホーム「対応が必要」を廃止し、期限切れ/今日のリマインダー/リマインド未登録/今週の予定の4区分に再構成

### 2026-08-09 — ホームの並べ替え(空の区分を下に送る)を撤回

- **Problem:** #98 で「中身のある区分を先に、空の区分を後ろに」という並べ替えを入れた。私は「空＝画面上部を占める価値がない」と判断したが、ユーザーから前提が逆だと指摘された。**「今日のリマインダーは無い」ことは、この画面で最初に確認したい答えそのもの**であり、空であることは価値の無さを意味しない。加えて、件数で位置が動くと毎日ホームを開くたびに「今日の分はどこにあるか」を探し直すことになる。
- **Decision:** #98 の並べ替えを撤回する。並びは **今日のリマインダー → 期限切れ → 今週の予定** の意味的な優先順位で固定し、件数では動かさない。定義順そのものも「期限切れ→今日」から「今日→期限切れ」へ変更した(今日やることが先、取りこぼしが次)。

### 2026-08-09 — コピーの見た目をバッジ経由からアイコン付き細字リンクに変更(2段階の撤回を含む)

- **Problem:** ホームのコピー操作(`.btn.sm`)が枠線・地色つきで、行の情報より視覚的に重く見えるとユーザーから指摘された。銘柄トップの「メモ・注目 N」バッジと同じ見た目にすることと、リマインダー件数もバッジで表現することを求められた。

- **Decision(最終):**
  1. 件数バッジは廃止。`.meta` に `${g.length}件・${タイトル}` として文字で表す(4区分再構成前の元の表現)。単一銘柄行は `.ttl` のみ(バッジもコピーリンクも無し)。
