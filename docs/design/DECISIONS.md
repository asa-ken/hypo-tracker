# DECISIONS.md

追記型の意思決定ログ。既存判断を再検討するときも過去エントリを削除・上書きせず、新しいエントリを追加する。

## エントリ形式
- **Date:** YYYY-MM-DD
- **Problem:** 問題
- **Decision:** 採用した判断
- **Reason:** 判断理由
- **Evidence:** 実測、ユーザー行動、テスト、画素測定等
- **Status:** 採用 | 撤回

### 2026-08-09 — 角丸クリップの残色
- **Problem:** 角丸クリップの縁に下の要素の色が残った。目視とCSS契約テストでは消えたと誤判定した。
- **Decision:** 切り抜き12pxに対して子要素の角丸を16pxにする。

- **Status:** 採用

### 2026-08-09 — 無検査だったデザイン契約を機械検査下に置く
- **Problem:** `design.js` は font-size / gap / 主要4画面の44px しか見ておらず、色トークン・`esc()`/`escArg()` の使い分け・シート内のタップ領域が無検査だった。文書側には「design.js が検査する」と書かれており、実装と食い違っていた。
- **Decision:** `colortoken.js` / `escuse.js` / `sheettap.js` の3スイートを追加。`DESIGN_SYSTEM.md` の各項目に「検査あり/なし/範囲」を明記した。
- **Reason:** テストが通ることを遵守の証拠にできない項目があると、自律ループが誤った安心を得る。
- **Evidence:** 負のテストで、色の追加・トークン削除・onclick内の `esc()` 誤用・HTML本文への `escArg()` 混入が、いずれも検出されることを確認した。
- **Status:** 採用

### 2026-08-09 — ホーム「今日のリマインダー」の表示が実態と乖離

- **Problem:** ホームの「対応が必要」内チップ「今日のリマインダー N」は、実装上 `DB.reminders.filter(r=>!r.paused)`(休止していない全リマインダー)を指し、日付での絞り込みが一切ない。テストデータで検証すると、表示された3件の実際の次回実行日(`calcNextFire`)は8/10・8/28・9/25で、今日(2026/8/9)が期限のものは0件だった。それでも常に「今日の」と表示され、「対応が必要」の件数にも常時加算される。BACKGROUND.md 7.1で撤回した「要更新」「鮮度切れ」等と同種の、根拠のない義務感を生む表示。
- **Decision:** チップ・トースト文言から「今日の」を外し、「リマインダー N」「リマインダーはありません」「確認プロンプトをコピーしました」に変更した(3箇所)。フィルタ条件・件数・ボタン・並び順など挙動は一切変更していない。外部AIへ渡すプロンプト本文中の「今日の確認事項を…」は運用テキストとして対象外にした。
- **Reason:** 表示文言だけを実態に合わせることで、情報アーキテクチャ・主要ワークフロー(何を対象にするか)を変えずに認知負荷(誤解を招く"今日"主張)を解消できる。フィルタを実際に「今日期限のものだけ」に絞る変更は、ホーム画面の中心的なワークフローを変えることになり、ユーザー確認が必要な範囲(情報アーキテクチャ・主要ワークフロー変更)に該当するため、今回は行わなかった。
- **Evidence:** テストデータで実際に `calcNextFire` を計算し、表示された3件のうち今日が期限のものが0件であることを確認(スクリーンショット・DOM測定・実データ)。`npm test` 121件・`npm run e2e` 51スイートいずれも変更前後で結果同一(green)。DOM測定(タップ領域・`#view.scrollHeight`)も変更前後で同一。
- **未解決事項:** 「休止していない全リマインダーを毎回対応必要として出す」という設計自体(フィルタに日付条件がないこと)が意図的な仕様か、実装漏れかは今回判断していない。もし「今日期限のものだけを目立たせたい」という要望があれば、フィルタ変更(主要ワークフロー変更)としてユーザーへ提案する。
- **Status:** 採用

### 2026-08-09 — シート内のタップ領域44px
- **Problem:** シートを実測したところ、指標の管理の「表示中/非表示中」バッジが36px(12個)、指標編集とリマインダー追加の `select` が43pxで、44pxの下限を割っていた。主要4画面しか見ていない `design.js` では検出できなかった。
- **Decision:** `.stat` の `min-height` を36px→44px、`select` に `min-height:44px` を追加。`metstat.js` の閾値も36→44へ引き上げた。
- **Reason:** アクセシビリティは Decision Hierarchy の最上位。selectは43pxで、あと1pxという「気づかれない不足」だった。
- **Evidence:** 修正前に `sheettap.js` が6項目落ちることを確認してから修正した。
- **Status:** 採用
